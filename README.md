# Лаборатори №6 — Category-Partition ба PICT

**Оюутны нэр:** С.Туяацэцэг
**Оюутны код:** B210910804

## A1. Сонголт ба төлөөлөх утгууд

| Параметр | Сонголт | Жишээ |
|---|---|---|
| From | Valid / Frozen / Missing | A001 / A002 / A999 |
| To | Valid / Missing / SameAsFrom | B001 / B999 / A001 |
| Amount | Zero / Normal / OverBalance / OverLimit | 0 / 100 / 1500 / 900 |
| Currency | Same / Different | MNT / USD |

Орчны нөхцөл: A001 данс 1000 MNT үлдэгдэлтэй, өдрийн үлдсэн лимит 800 MNT. Валютын ханшийг 1 USD = 3500 MNT гэж туршилтын өгөгдөлд тогтоосон.

## A2. Хязгаарлалтууд

| Сонголт | Тэмдэглэгээ | Үндэслэл |
|---|---|---|
| From Missing | ERROR | Эх данс байхгүй |
| From Frozen | ERROR | Данс царцаагдсан |
| To Missing | ERROR | Хүлээн авах данс байхгүй |
| To SameAsFrom | ERROR, IF | Өөр рүүгээ шилжүүлж болохгүй |
| Amount Zero | ERROR, SINGLE | Тэг утгыг тусад нь шалгана |
| Amount OverBalance | ERROR | Үлдэгдэл хүрэлцэхгүй |
| Amount OverLimit | ERROR | Өдрийн лимит хэтэрнэ |
| Currency Different | IF | Ханш хөрвүүлсний дараах дүнг шалгана |

Бүрэн олонлог: 3 × 3 × 4 × 2 = **72**.

Сонгосон IF хязгаарлалтууд: From Missing үед Amount Normal; To Missing үед Amount Normal; To SameAsFrom үед From Valid.

Эдгээр хязгаарлалтын дараах зөвшөөрөгдсөн хослол: **72 → 32**.

Олон алдааны давуу эрэмбэ: **From → To → Amount → Currency**. Энэ нь кодоор батлагдсан дүрэм биш, тестийн хүлээгдэх үр дүнг нэг утгатай болгох зорилготой сонголт.

## B. PICT pairwise туршилт

PICT-ийн эх кодыг repository-оос гадна бүтээсэн. Нотолгоо: `results/pict-build.txt`.

Моделиуд: `browser.model`, `transfer-nc.model`, `transfer.model`, `transfer-neg.model`.

PICT нь greedy арга ашигладаг тул заавал хамгийн бага мөртэй covering array үүсгэхгүй. Category-Partition нь алдааны утга болон oracle-ийг тодорхойлоход, PICT нь параметрүүдийн хослолын хамралтыг үүсгэхэд тохиромжтой.

### B1. Browser model — Pairwise covering array

Лекцийн браузерын жишээг `browser.model` файлд бичиж, PICT ашиглан 2-way болон 3-way хослолууд үүсгэсэн.

Модель нь Content, Cookies, Popups, Addons, Attacks, Forgeries гэсэн зургаан параметртэй.

Бүрэн боломжит хослолын тоо:

3 × 3 × 2 × 2 × 2 × 2 = **144 мөр**

| Туршилт | Мөрийн тоо | Нотолгоо |
|---|---:|---|
| Бүрэн олонлог | 144 | Тооцоолол |
| Browser 2-way | 10| `results/browser-2way.txt` |
| Browser 3-way | 20| `results/browser-3way.txt` |

**2-way болон 3-way харьцуулалт**

2-way арга нь параметрүүдийн боломжит хоёр утгын хослолуудыг хамарна. Харин 3-way нь гурван параметрийн утгуудын хослолыг хамрах шаардлагатай тул ихэвчлэн илүү олон тест үүсгэдэг.

Лекцийн жишээнд 2-way тестийг гараар 9 мөрөөр төлөөлүүлсэн. PICT-ийн үр дүн үүнээс зөрж болох бөгөөд шалтгаан нь PICT greedy алгоритм ашигладагтай холбоотой. Энэ алгоритм бүх шаардлагатай хослолыг хамрахыг зорьдог ч хамгийн цөөн мөртэй шийдэл гаргах баталгаа өгдөггүй.

Бүрэн олонлогийн 144 хослолтой харьцуулахад PICT нь тестийн тоог багасгаж, хослолын хамралтыг хадгалах боломж олгосон.

### B2. Банкны шилжүүлгийн PICT model

Банкны шилжүүлгийн `POST /transfer` функцэд дараах гурван модель боловсруулсан.

- `transfer-nc.model` — Хязгаарлалтгүй модель.
- `transfer.model` — IF хязгаарлалттай модель.
- `transfer-neg.model` — Алдааны утгуудыг `~` тэмдэглэгээгээр ялгасан модель.

**Моделиудын харьцуулалт**

| Модель | Үүссэн мөр | Зорилго |
|---|---:|---|
| transfer-nc | 13| Бүх утгыг чөлөөтэй хослуулах |
| transfer | 12| IF хязгаарлалтыг мөрдүүлэх |
| transfer-neg | 16| Нэг мөрөнд олон сөрөг утга оруулахгүй байх |

Хязгаарлалтгүй загварын бүрэн олонлог 72 боломжит хослолтой. Харин A2 хэсэгт сонгосон IF нөхцөлүүдийн дараа зөвшөөрөгдөх хослолын тоо 32 болсон. Эдгээр нь бүрэн олонлогийн тооцоо бөгөөд PICT-ийн үүсгэсэн тестийн мөрийн тооноос ялгаатай.

**Хязгаарлалтгүй модель**

`transfer-nc.model`-ийн гаралтад хэд хэдэн алдаа зэрэг орсон мөрүүд үүссэн.

Жишээ нь:

`Missing | SameAsFrom | Zero | Same`

Энэ мөрөнд эх данс байхгүй, хүлээн авах данс эх данстай ижил, шилжүүлэх дүн тэг гэсэн хэд хэдэн алдаа зэрэг байна.

Тогтоосон алдааны давуу эрэмбийн дагуу эхлээд `ERROR_NO_FROM` буцах ёстой гэж үзнэ. Энэ тохиолдолд бусад алдааг тусад нь шалгах боломжгүй бөгөөд error masking үүснэ.

**IF хязгаарлалттай модель**

`transfer.model` файлд дараах нөхцөлүүдийг нэмсэн.

- From Missing үед Amount Normal.
- To Missing үед Amount Normal.
- To SameAsFrom үед From Valid.

Ингэснээр сонгосон хязгаарлалтад нийцэхгүй хослолуудыг хассан. Гэхдээ хязгаарлалттай модельд ч зарим алдаа давхар илэрч болох тул хүлээгдэх үр дүнг тогтоосон давуу эрэмбээр тодорхойлно.

**Negative модель**

`transfer-neg.model`-д ERROR утгуудын өмнө `~` тэмдэг тавьсан.

PICT нь сөрөг утгыг тусгайлан авч үздэг тул нэг мөрөнд олон сөрөг утга зэрэг оруулахгүй. Энэ нь тус бүрийн алдааны ангийг тодорхой шалгахад тохиромжтой.

Гэхдээ `~` тэмдэглэгээ нь бүх бизнесийн дүрмийг орлохгүй. Жишээлбэл, валютын ханш, үлдэгдэл, лимитийн хамаарал зэрэгт IF нөхцөл болон туршилтын өгөгдлийн тохиргоо шаардлагатай хэвээр байна.

**Happy path болон error masking**

`transfer-neg.txt` гаралт дахь `Valid | Valid | Normal | Same` нь happy path буюу амжилттай шилжүүлгийн нөхцөл юм.

`transfer-nc.txt`-д олон алдаатай мөрүүд үүссэн бол `transfer-neg.txt`-д нэг алдаатай нөхцөлүүдийг ялгахад хялбар болсон.

Эдгээрээс сонгосон гурван мөрийг B3 хэсэгт бодит тест кейс болгон боловсруулсан.

## B3. PICT гаралтаас боловсруулсан тест кейс

PICT-ийн гаралтаас нэг амжилттай, хоёр алдаатай нөхцөлийг сонгон тест кейс боловсруулсан. Эдгээр нь кодоор ажиллуулсан тест биш, шилжүүлгийн функцийн спецификацид тулгуурласан тестийн загвар юм.

### TC01 — Амжилттай шилжүүлэг

**PICT мөр:** `Valid | Valid | Normal | Same`

**Эх сурвалж:** `results/transfer-neg.txt`

- **Setup:** A001 данс идэвхтэй, үлдэгдэл 1000 MNT, өдрийн үлдсэн лимит 800 MNT. B001 данс хүчинтэй.
- **Input:** `{"from":"A001","to":"B001","amount":100,"currency":"MNT"}`
- **Oracle:** HTTP 201, `{"result":"OK"}`

### TC02 — Эх данс байхгүй

**PICT мөр:** `~Missing | Valid | Normal | Same`

**Эх сурвалж:** `results/transfer-neg.txt`

- **Setup:** A999 данс байхгүй, B001 данс хүчинтэй.
- **Input:** `{"from":"A999","to":"B001","amount":100,"currency":"MNT"}`
- **Oracle:** HTTP 200, `{"result":"ERROR_NO_FROM"}`

### TC03 — Шилжүүлгийн дүн тэг

**PICT мөр:** `Valid | Valid | ~Zero | Same`

**Эх сурвалж:** `results/transfer-neg.txt`

- **Setup:** A001, B001 дансууд хүчинтэй. A001 дансны үлдэгдэл 1000 MNT, өдрийн үлдсэн лимит 800 MNT.
- **Input:** `{"from":"A001","to":"B001","amount":0,"currency":"MNT"}`
- **Oracle:** HTTP 200, `{"result":"ERROR_BAD_AMOUNT"}`

### Хоёр аргын харьцуулалт

Category-Partition аргаар сонголт бүрийн алдааны утга болон хүлээгдэх үр дүнг тодорхойлсон. PICT нь параметрүүдийн хослолыг автоматаар үүсгэсэн. Хязгаарлалтгүй `transfer-nc.model`-ийн гаралтад хэд хэдэн алдаа нэг мөрөнд орж байгаа нь харагдсан. Харин `transfer-neg.model`-ийн `~` тэмдэглэгээ нь нэг мөрөнд олон сөрөг утга орохыг хязгаарлаж, error masking асуудлыг багасгасан.

## Дүгнэлт

Энэ лабораторид Category-Partition болон PICT гэсэн хоёр аргыг ашиглан тест тохиолдол боловсруулсан. Category-Partition аргаар банкны шилжүүлгийн параметрүүдийг сонголтуудад хуваасан. Сонголт бүрд төлөөлөх утга тодорхойлж ERROR, SINGLE, IF тэмдэглэгээ хэрэглэсэн. Олон алдаа зэрэг гарахад хүлээгдэх үр дүн тодорхойгүй тул давуу эрэмбэ сонгосон. PICT-ээр параметрүүдийн pairwise хослолыг автоматаар үүсгэсэн. Хязгаарлалтгүй модельд олон алдаатай хослол үүсэх боломжтой. Сөрөг утгыг ~ тэмдэглэгээгээр илэрхийлснээр error masking асуудлыг багасгаж болно. Гараар боловсруулсан тестүүд алдааны утга, хүлээгдэх үр дүнг илүү тодорхой харуулсан. Харин PICT нь олон хослолыг системтэйгээр хамрахад давуу талтай. Иймээс эдгээр аргыг хамтад нь ашиглах нь илүү тохиромжтой гэж үзсэн.
